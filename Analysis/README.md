# 现有采集数据分析

本目录用于逐类记录现状与分析结论，先讨论数据语义，再开展存储和版本设计。

## 分析阶段约定

- 现有采集流程继续写本地快照，采集器及 snapshot 定义保持不变。
- 分析不预设必须使用 MySQL 或 MongoDB，也不据此直接实施数据库改造。
- 一次聚焦一类数据，区分用户确认的业务事实、代码能够证明的行为、分析判断和待讨论事项。
- 每类数据先梳理实体、字段来源、变化特点、缺失含义及时间语义，再输出结论。
- 已有 `DATA_PERSISTENCE_DESIGN.md` 仅作为先前草案；后续应以逐项讨论形成的结论为依据，不作为已确认设计。

## 分类方法

分析时分别回答两个问题，不将它们混为一谈：

1. **如何变化**：稳定标识、相对稳定属性、集合成员变化、部署配置变化、运行观察变化、采集元信息变化。
2. **来自哪里**：当前类型的直接采集字段、其他快照补充的数据、规则推断、页面计算/汇总。

“相对稳定”表示通常少变，不表示永远不可修改。“当前值变化”不必然证明发生了一次发布、删除或重启事件。
