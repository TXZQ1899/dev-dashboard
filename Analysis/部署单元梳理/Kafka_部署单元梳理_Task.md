# Kafka 部署单元梳理 Task

状态：待实施；先执行候选梳理和只读核查，确认结果后写入。共同规则见 [00-共同约束](00-共同约束.md)。本任务不表示已发现实际实例或集群。

## 目标与输出

- 创建技术类型为 `Kafka`、单元类型建议为 `MIDDLEWARE` 的部署单元；名称为 `Kafka_cluster_序号`。明确独立部署同样使用此命名，并有一个节点。
- 输出候选进程清单、应用关联排除清单、拟创建单元与节点、证据和置信度、待核实项、覆盖与失败情况；环境初始为「待识别」。类型归类为设计建议，实施时须与现有目录枚举及产品口径核对。

## 专项核查和归并任务

- 识别 Kafka broker 和 KRaft controller 的 Java 主类、实际配置与角色；排除 tools、客户端、Connect 等不同服务。识别容器和多实例。
- 区分 ZooKeeper 模式与 KRaft 模式，核实有效配置、broker.id/node.id、listeners/advertised.listeners、角色及只读集群元数据。使用运行时 cluster ID 和成员视图交叉核对，区分 broker 与 controller；不同 Endpoint 保留地址语义。
- 用 cluster ID 及一致的成员信息归并，控制器角色是否作为该单元成员按运行角色明确记录；ZooKeeper 是依赖，不是 Kafka 节点。仅共享 ZooKeeper、bootstrap 地址或配置模板不证明同集群。
- 单节点 broker 或组合角色须核实集群模式及成员视图后才单节点；KRaft quorum 不完整或身份冲突保留待核实。

## 执行步骤

1. 从已完成快照建立本类型候选，记录每台资产的采集状态、进程与直接/推断端口；评估 DevOps 关联，排除已关联项，冲突保留待核实。
2. 确认版本和部署方式，按上述专项规则定位有效配置，实施最小只读检查；分别保存观察时间、节点身份、Endpoint、证据来源与限制。
3. 汇总节点视图，识别单节点、多节点和未解析成员；给出证据与置信度，列出冲突、无法访问主机和可能的同机多实例，生成导入预览。
4. 核对预览并确认后，事务写入单元、待识别环境、实例、来源观察及变更；重复执行保持身份和序号稳定，失败回滚。
5. 验证容器运行、持久化和结果可追溯；输出覆盖范围与剩余未解决项，不将未观察到等同停机。

## 专项测试与验收

- 同 cluster ID 的 broker/controller 记录角色并归组；不同 cluster ID 共享 ZooKeeper 不合并。
- 广告地址不可解析、controller 独立部署、只看到一个 broker、工具进程均覆盖。

- 执行共同约束中的通用测试；检查不同证据环节置信度独立、敏感信息遮盖、较旧及不完整观察不能误更新、预览与落库一致。
- 验收时逐条核对单元名称、环境、节点、证据、未解析原因及排除原因；不可将无法证明的集群或独立部署写成确定结果。
