# Jenkins 部署单元梳理 Task

状态：当前快照中发现的 3 个 controller 已按用户确认分别建档；agent 关系与未采集范围仍未知。共同规则见 [00-共同约束](00-共同约束.md)。

## 目标与输出

- 创建技术类型为 `Jenkins`、单元类型建议为 `OTHER` 的部署单元；名称为 `Jenkins_cluster_序号`。明确独立部署同样使用此命名，并有一个节点。
- 输出候选进程清单、应用关联排除清单、拟创建单元与节点、证据和置信度、待核实项、覆盖与失败情况；环境初始为「待识别」。类型归类为设计建议，实施时须与现有目录枚举及产品口径核对。

## 专项核查和归并任务

- 识别 Jenkins controller 的 Java 主类、war、服务配置或容器；排除构建任务启动的 Java、agent 和客户端进程。核实端口及 Jenkins home 的实际来源。
- 记录 controller 身份、运行配置和已确认的部署/HA 编组；如果有授权，只读核对版本支持的管理视图。agent 是执行节点，不默认当作 controller 集群节点；插件相关 HA 模式必须以实际产品及配置为准。
- 相同 Jenkins home、共享存储、相同插件或同一反向代理不足以证明多个 controller 属于同一个集群；没有明确 HA 编组证据时保留待核实。
- 经确认的独立 controller 为单节点；agent 关联、共享目录和负载均衡不自动合并。

## 执行步骤

1. 从已完成快照建立本类型候选，记录每台资产的采集状态、进程与直接/推断端口；评估 DevOps 关联，排除已关联项，冲突保留待核实。
2. 确认版本和部署方式，按上述专项规则定位有效配置，实施最小只读检查；分别保存观察时间、节点身份、Endpoint、证据来源与限制。
3. 汇总节点视图，识别单节点、多节点和未解析成员；给出证据与置信度，列出冲突、无法访问主机和可能的同机多实例，生成导入预览。
4. 核对预览并确认后，事务写入单元、待识别环境、实例、来源观察及变更；重复执行保持身份和序号稳定，失败回滚。
5. 验证容器运行、持久化和结果可追溯；输出覆盖范围与剩余未解决项，不将未观察到等同停机。

## 专项测试与验收

- 独立 controller + 多个 agent → 一个单节点单元，agent 单独记录为依赖/待定。
- 两 controller 共享存储但无 HA 证据不合并；构建子进程不创建实例。

- 执行共同约束中的通用测试；检查不同证据环节置信度独立、敏感信息遮盖、较旧及不完整观察不能误更新、预览与落库一致。
- 验收时逐条核对单元名称、环境、节点、证据、未解析原因及排除原因；不可将无法证明的集群或独立部署写成确定结果。
