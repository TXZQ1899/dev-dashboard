# 进程补充部署单元：共同约束

状态：设计任务，未实施。每次只启用一种组件，先预览核对，再确认写入。

## 输入与边界

- 使用当前已完成版本的 JumpServer 资产及 inspection（checkedAt、loginStatus、processStatus、processes、appPorts、docker），并记录版本及各资产实际采集时间；应用数据使用对应版本的 DevOps 快照。快照不同步、过期或不完整须显示。现有 Process 无直接应用 ID；关联依据必须保留。
- 已关联 DevOps 应用 ID 的进程不新建单元。有候选但归属不唯一、冲突或无法充分排除关联时，保留候选并暂停创建；展示层 `-` 不证明无关联。关联评估应与现有启发式区分，保留所有候选，不按第一个命中作事实。
- 先识别候选，再区分进程、服务实例、集群；父子进程及代理不能直接当成实例。容器进程和发布端口须区分直接观察和推断，代理不等同服务；同机同类型多实例不可按 IP 合并。采集器没有需要的字段时先设计定向只读核查，不更改原快照。
- 环境一律初始显示「待识别」。现有数据库 CHECK 仅允许 TEST / SIMULATION / PRODUCT，须新增迁移及相应查询、展示和后续转换，不将 UNKNOWN 混同于正式环境；转换保留 UUID 和变更历史。
- 所有明确独立部署也命名为 `类型_cluster_序号`，作为一个节点的单元。未确认其独立或集群归属的候选，不因只有一个观察节点而视为独立部署。集群存在但部分成员不可达时保留已确认成员及未解析成员，明确覆盖范围；不得推断其为单节点。
- 单元 UUID 稳定，序号按规范类型持久化分配、并发唯一、不重用、不随快照排序或重启变化；code 与 name 的唯一约束及长度在迁移中明确。实例匹配使用可靠的组件身份、资产/Endpoint 与来源别名；PID + startedAt 仅标识一次进程观察，PID 或 IP 单独不能作为长期身份。实例迁移、合并拆分或新旧多候选时保留冲突并人工确认，不自动改写历史。
- 每条观察保留来源版本、定位、采集/核查时间、采集范围、规则版本、匹配依据、置信度和脱敏证据。EXACT / INFERRED / AMBIGUOUS / UNKNOWN 分别使用；进程类型、应用关联、节点身份、集群归属、端口归属分别评估，不继承其他环节的置信度。IP + port + protocol 优先，DNS、通配地址、NAT 与容器映射保留原始表达及解析依据。
- 服务器核查限于最小必要的只读操作；先校验资产与进程身份、权限和实际配置路径，再读取白名单字段。按组件版本/部署方式确认命令可用性；命令不可用、授权不足、超时或版本不支持时记录 UNKNOWN，不能当空结果。不得执行重启、修改配置、选主、变更成员或写入服务；不输出密码、令牌、密钥或完整敏感配置。管理接口需要凭据或权限时仅在已有授权和合适的只读凭据下调用，不绕过认证；否则保持待核实。
- 按来源和覆盖范围处理更新：不完整、失败、权限不足、较旧或不可排序的观察不覆盖较新结论，也不标记缺失。完整且范围明确时才允许 NOT_OBSERVED，仅表示未再观察到，不表示停机或删除。成员证据变化产生待复核变更，不自动合并或拆分。导入应幂等、事务提交、记录变更；任务与持久数据运行于 environment-web 容器及配置数据卷/MySQL 卷。

## 通用交付与验收

1. 实施前确认本类型识别规则、证据阈值、读操作与版本适配；按本类型执行，不批量实施其他类型。
2. 展示候选、已排除应用、已确认单元和节点、待核实/冲突、权限失败、来源时间、覆盖率和脱敏证据；提供可审阅预览及确认后的导入结果。
3. 对已确认关系写入部署单元、待识别环境、实例、来源、不可变观察和变更记录；无法确认的部分保留待核实，不捏造关系。
4. 小型脱敏 fixture 覆盖：多节点、明确单节点、未知归属、同机多实例、多进程、容器/代理、已关联应用、关联冲突、端口及身份歧义、权限/部分采集、重启、重复导入、旧快照、并发序号、事务失败与恢复；验证容器内运行和持久化。
5. 输出本类型清单、证据与未解决项、规则版本、测试结果和覆盖局限。核查工作不能推断实时健康或完整库存。
