# MySQL 部署单元梳理 Task

状态：50 个用户确认的 DMS 云实例及 17 个用户指定的进程已分别建档；进程的复制和应用关联、无云实例 ID 的 DMS 记录仍待核实。共同规则见 [00-共同约束](00-共同约束.md)。

## 目标与输出

- 创建技术类型为 `MySQL`、单元类型建议为 `DATABASE` 的部署单元；名称为 `MySQL_cluster_序号`。明确独立部署同样使用此命名，并有一个节点。
- 输出候选进程清单、应用关联排除清单、拟创建单元与节点、证据和置信度、待核实项、覆盖与失败情况；环境初始为「待识别」。类型归类为设计建议，实施时须与现有目录枚举及产品口径核对。

## 专项核查和归并任务

- 识别 mysqld/mariadbd 服务及实际配置和数据目录；区分客户端、代理及多实例。MySQL 与 MariaDB 技术类型边界先确认，不能仅凭兼容协议混同。
- 核对生效配置、server_uuid/server_id、监听 Endpoint、复制状态；按实际版本识别异步复制、Group Replication、InnoDB Cluster 等模式，授权下以只读状态交叉核实成员和角色，不保存账号密码。
- 以运行中复制/组复制成员证据及节点身份归并；相同 server_id、配置模板、备份来源或代理地址不证明同一集群。代理或管理服务不是数据库节点；同一服务器不同端口和数据目录可为不同实例。
- 明确无复制/HA 的独立实例为单节点；复制停止、权限不足或身份克隆冲突时保留未知并核实历史及运行状态。

## 执行步骤

1. 从已完成快照建立本类型候选，记录每台资产的采集状态、进程与直接/推断端口；评估 DevOps 关联，排除已关联项，冲突保留待核实。
2. 确认版本和部署方式，按上述专项规则定位有效配置，实施最小只读检查；分别保存观察时间、节点身份、Endpoint、证据来源与限制。
3. 汇总节点视图，识别单节点、多节点和未解析成员；给出证据与置信度，列出冲突、无法访问主机和可能的同机多实例，生成导入预览。
4. 核对预览并确认后，事务写入单元、待识别环境、实例、来源观察及变更；重复执行保持身份和序号稳定，失败回滚。
5. 验证容器运行、持久化和结果可追溯；输出覆盖范围与剩余未解决项，不将未观察到等同停机。

## 专项测试与验收

- 已核实一主两从或 group replication 成员 → 一个单元；两个独立 MySQL → 不同序号单元。
- 克隆 UUID 冲突、同机多实例、代理、失联副本及无权限均不误归并。

- 执行共同约束中的通用测试；检查不同证据环节置信度独立、敏感信息遮盖、较旧及不完整观察不能误更新、预览与落库一致。
- 验收时逐条核对单元名称、环境、节点、证据、未解析原因及排除原因；不可将无法证明的集群或独立部署写成确定结果。
