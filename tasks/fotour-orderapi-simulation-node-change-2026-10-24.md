## 2. 如何获取 DevOps 平台链接

### 2.1 从 EnvScope 的“应用列表”获取

1. 打开当前 EnvScope 页面。本次连接的页面来源为 `http://10.58.5.44:3001`。
2. 在导航中进入“应用列表”，对应页面路径为 `/applications`。
3. 在“搜索应用、HTTP 名、端口或 IP…”搜索框中输入 `fotour-orderapi`。
4. 找到应用名称完全等于 `fotour-orderapi` 的行，核对名称，避免选到相似应用。
5. 该行的应用名称本身就是超链接。可以直接点击，或右键复制链接地址。
6. 应用名称链接的提示文字是“在新标签页打开 DevOps 应用详情”。

本次获得的链接：

```text
http://devops.folidaymall.com/#/project/application/info?id=1487
```

[打开 fotour-orderapi 的 DevOps 应用详情](http://devops.folidaymall.com/#/project/application/info?id=1487)

该链接打开的是 DevOps 应用详情，页面内提供各环境的实例操作入口。

### 2.2 链接是如何生成的

应用列表源码 `environment-web/app/applications/page.tsx` 使用以下规则生成链接：

```ts
`http://devops.folidaymall.com/#/project/application/info?id=${encodeURIComponent(a.id)}`
```

其中 `a.id` 为 DevOps 应用 ID。本次 `fotour-orderapi` 的 ID 是 `1487`，因此得到上述地址。

这里需要使用应用 ID。部署记录中的 `deploy` 是实例 ID，不能代替应用 ID；`http` 字段 `/fotour-orderapi` 也不是 DevOps 平台链接。

### 2.3 必要时从 Docker context lenovo 核对应用 ID

本次数据查询读取 `lenovo` 中 `envscope-local` 容器的数据卷，以 `/data/current.json` 指向的激活版本为准。下面是只读查询示例，只输出目标应用的信息：

```bash
docker --context lenovo exec -i envscope-local python3 - <<'PY'
import json
from pathlib import Path
from urllib.parse import quote

root = Path('/data')
current = json.loads((root / 'current.json').read_text())
version_dir = root / 'versions' / current['id']
snapshot = json.loads((version_dir / 'snapshot.json').read_text())

matches = [
    app for app in snapshot.get('apps', [])
    if app.get('name') == 'fotour-orderapi'
]

print('激活数据版本:', current['id'])
print('DevOps 采集时间:', snapshot.get('collectedAt', ''))
print('同名应用数量:', len(matches))
for app in matches:
    app_id = str(app['id'])
    url = (
        'http://devops.folidaymall.com/'
        '#/project/application/info?id=' + quote(app_id, safe='')
    )
    print(json.dumps({
        '应用名称': app['name'],
        '应用ID': app_id,
        'DevOps链接': url,
        '仿真部署': [
            {'ip': row.get('ip'), 'port': row.get('port') or app.get('port')}
            for row in app.get('envs', {}).get('SIMULATION', [])
        ],
    }, ensure_ascii=False))
PY
```

本次查询时，激活版本为 `20261023-180013-994978`，DevOps 采集时间为 `2026-10-23 18:10:15`（北京时间）。查询得到应用 ID `1487`，当时的仿真部署 IP 为 `10.58.9.76`。

**采集快照有自己的时间点。后续浏览器中的扩容、停止、缩容操作，不会自动证明旧采集快照已经同步；本次操作结果以 DevOps 页面实际显示为准。**

### 9.4 缩容不成功时的强制缩容

以下补充来自 2026-11-02 对 `10.58.10.94` 仿真应用的节点调整，以及此前对其他仿真节点的操作经验；不是说 `fotour-orderapi` 在 2026-10-24 的操作曾经失败。`10.58.10.94` 批次中，`live-center-offline`（应用 ID `1860`）和 `fcrs-product-pump`（应用 ID `1425`）的停止任务失败，之后由用户执行强制缩容；页面核实两者的原节点卡片均已消失，`10.58.9.62` 的新节点卡片仍在，状态为“待部署”。

遇到停止或缩容不成功时，按当前应用和页面状态处理：

1. 先核对应用名称、应用 ID、选中的“仿真环境”、原节点 IP 和新节点卡片；从原节点的“运行详情”核对任务失败的步骤和资源绑定 IP。卡片显示 IP 与任务资源绑定 IP 可能不同，不能仅凭卡片推断任务实际作用的主机。若存在不一致，先核实该资源的实际状态，再处理该实例。
2. 若任务仍显示“运行中”或页面尚未刷新，继续观察，不要重复提交。若原节点卡片已经消失，直接执行第 6 步；若任务失败且原节点仍在，按本次迁移要求继续强制缩容。
3. 在**原节点卡片**右上角再次点击红色垃圾桶。出现“确定缩容……机器？”时，核对其中 IP 是本次原节点，再点击“确定”。
4. 若页面随后出现“强制缩容”警告，核对当前应用、环境、原节点和警告内容，再点击警告框中的“确定”。此前页面曾出现“强制缩容,主机没有查询到！？”或“强制缩容,未知异常？”；实际文字以当前页面为准，不应将警告文字当作主机状态的独立证明。
5. 等待本次操作结束并刷新核对。如果原节点仍在，且页面已经显示失败或明确要求继续强制缩容，可以再次从该原节点的删除图标进入，重复核对缩容 IP 和强制缩容警告后确认。**有时需要执行两次强制缩容，原节点才会消失；次数不是完成判据，任务运行中不能连续点击。** 如果两次后仍未消失，记录应用 ID、原节点、任务状态及警告，继续核查，不把提交提示视为完成。
6. 最终以 DevOps 仿真环境页面为准，确认原节点卡片消失、新节点卡片仍在，并记录新节点状态。必要时刷新页面再次核对；“操作成功”或“缩容成功”提示只证明提交或接口响应，不单独证明原节点已移除。

**强制缩容后的卡片消失只证明 DevOps 实例记录已移除，不证明原主机上的进程已停止、文件已卸载或流量已切换。** 对停止任务失败的实例，保留失败记录并单独核实实际进程和流量；新节点若为“待部署”，也不能认定服务已启动。

## 10. 浏览器自动化复现时的定位细节

### 10.1 每一步都使用当前页面状态

本次工具提供的无障碍树会为元素分配数字索引。不同页面状态下，同一按钮的索引可能变化；弹窗打开、列表筛选、后台刷新都会影响索引。

推荐的交互顺序是：

```text
读取 getAXState()
→ 依据文字、角色和所属区域确认目标
→ 点击或输入
→ 再读取 getAXState()
→ 核对状态变化
```

不要照抄本次某一步的数字索引直接执行下一次操作。比如页面中有两个“停止”按钮，应通过其所属卡片的 IP 确认目标。

### 10.2 各控件的定位与完成判据

| 操作 | 优先定位依据 | 操作完成后核对 |
|---|---|---|
| 打开应用 | 应用名称与 ID `1487` | 应用详情显示 `fotour-orderapi` |
| 选择环境 | 角色为 `tab`、文字为“仿真环境” | `selected` 状态及仿真实例内容 |
| 打开扩容窗口 | 当前环境内容区的“扩容”按钮 | 出现“扩容主机”弹窗 |
| 搜索 IP | “所有主机”区域下的文本框 | 回车后显示目标 IP 搜索结果 |
| 勾选 IP | 左侧结果中名称为 `10.58.9.62` 的复选框 | 勾选状态为真，或 `Value: 1` |
| 移入已选主机 | 两个列表之间的向右箭头 | 右侧列表出现 `10.58.9.62` |
| 提交扩容 | “扩容主机”弹窗底部的“确定” | 扩容成功提示及新增实例卡片 |
| 停止原节点 | IP 为 `10.58.9.76` 的卡片内“停止”按钮 | 停止状态“执行成功” |
