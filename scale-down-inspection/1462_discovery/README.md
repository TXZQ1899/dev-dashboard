# discovery 缩容巡检原型

在仓库根目录执行：

```sh
python3 scale-down-inspection/1462_discovery/run.py \
  --app-id 1462 --environment PRODUCT \
  --output scale-down-inspection/1462_discovery/results
```

串行输出阶段和日志传输进度。需要本机 Python 3、Docker CLI 和 curl，以及 `lenovo` Docker context；所有服务器访问仍由 `envscope-local` 经 JumpServer 执行。配置扫描读取卷内实际文件，不将空目录或原同步任务状态当作读取错误。

原始日志以压缩包保存在 `results/raw_logs/`，传输完成后检查 SHA-256；本地分析不将归档路径解压到文件系统。原始日志可能包含敏感数据，请控制访问及保留时间。日志通过进程目录、Logback 配置和标准输出文件发现，归档按修改时间选取近七天；无法保证覆盖所有日志或完整七天。归档在写入中变化、读取失败和大小上限均记录为不完整。

API 统计目前只识别 Apache/Nginx 常见 access log；查询字符串不写入报表。无法识别的格式标为未知，不代表无访问。无时区的 Spring ERROR/WARN 日志按服务器采集时的时区计算。日志解压分析上限为每个归档 256 MiB，超限时报告不完整。

Nginx 扫描当前版本归档和卷内已下载配置，按字面 `IP:端口` 识别后端；不使用历史采集状态决定结果，主机名或变量后端未展开。DNS 单独读取当前云 DNS 快照与容器的静态 DNS 数据，按已发现的入口域名及服务器 IP 查找；仅凭 IP 的匹配是服务器候选，不能确认应用归属，CNAME 只在相同来源、租户及可见范围内关联。

Kong 查询目前只配置了 1462 的生产环境，核对 Target、Service、Route，不核验健康状态。发现进程即将该项标为完成；进程匹配使用应用名参数或 jar 名，业务归属仍是推断。工作目录来自 `/proc/PID/cwd`，其他目录由参数或日志路径推导，均额外进行远端目录存在性检查。日志有文件且本地分析成功即标为完成；未识别 ACCESS LOG 会在说明中列出。目标服务器历史资源分析尚未实现，巡检入口因此始终返回非零状态；该报告不能单独作为缩容依据。

JVM 内存参数仅展示进程启动参数中的 `-Xms` 和 `-Xmx`；RSS 取 `/proc/PID/status` 的 VmRSS。`RSS / 启动参数 Xmx` 使用显式 `-Xmx` 计算；未明确设置或无法读取时留空。RSS 包含堆以外的驻留内存，比例可能超过 100%，不能当作 Java 堆使用率。归档和其中的嵌套 `.tar.gz` / `.gz` 在本地解压读取后分析，内容不解压成磁盘上的独立文件。

应用配置在容器内按环境目录、进程显式 profile 和公共配置候选读取；本地仅保存端点、URL 和文件摘要，不导出配置原文。文件快照版本与生效状态分别列出；无法解析的变量不会当作确定地址。URL 不导出认证信息或查询参数。

“引用URL”排除与关联组件在同一文件、同一行且主机和端口相同的声明；其余 URL 保留，不能仅凭列表认定第三方归属。Dubbo 角色未知时不生成服务记录，状态仍在汇总中保留。TCP Sheet 只展示精简后的聚合字段；不唯一的应用保留为待确认及候选，完整置信度和连接证据保存在原始 TCP 报告中。

Dubbo 只对配置明确声明的 ZooKeeper 注册中心查询默认 `/dubbo` 路径；未经确认的命名空间、其他注册中心类型、认证失败及不唯一的应用匹配均保留未知或部分结果。Consumer 未声明端口时留空，不用临时端口或部署端口补造。

TCP 检测通过 EnvScope 的单应用检查 API 串行执行，每台申请 300 秒观察，完整报告保存在 `results/tcp_reports/`，Excel 按对端 IP 和进程候选聚合。采样时间、上限、未解析原因和实际观察跨度沿用原始报告；短连接可能漏采。若明确需要重用已有报告，可传 `--tcp-reports <目录>`；脚本会核对快照版本、环境和请求时长，不匹配时不将其当作当前结果。

汇总中的上下游数量按各方向已观察到的对端 IP 加端口去重，不统计连接条数；采样达到上限时在汇总中提示不完整。配置汇总中组件按已识别的主机和端口去重，关联系统按“引用URL”中的主机和端口去重。Dubbo 角色无法识别时不会推断为非 Dubbo，汇总显示“未识别 Dubbo 角色”。
